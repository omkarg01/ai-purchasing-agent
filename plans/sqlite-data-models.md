# SQLite Data Models & Architecture Plan

## 1. Overview
This document specifies the initial database layer for the **AI Purchasing Agent**.
The database is built using **SQLite** with **SQLAlchemy 2.0 ORM** in a modular backend structure under `backend/app/models/` and `backend/app/database/`.

---

## 2. Models & Field Descriptions

### 2.1. `Product`
Represents the catalog of products that the business monitors and purchases.

| Field | Type | Modifiers / Constraints | Purpose & Rationale |
|---|---|---|---|
| `id` | Integer | PK, Autoincrement | Unique identifier for the product. |
| `name` | String(255) | Not Null, Index | Descriptive human-readable product name. |
| `sku` | String(100) | Not Null, Unique, Index | Stock Keeping Unit code used for unique inventory identification across systems. |
| `description` | Text | Nullable | Optional specifications or notes on the product. |

**Relationships & Deletion Rules:**
- `inventory`: One-to-One relationship with `Inventory` (cascades on delete).
- `demand_forecasts`: One-to-Many relationship with `DemandForecast` (cascades on delete).
- `supplier_products`: One-to-Many relationship with `SupplierProduct` (association model for Supplier M:N).
- `purchase_recommendations`: One-to-Many relationship with `PurchaseRecommendation` (`RESTRICT` on delete to preserve history).
- `purchase_orders`: One-to-Many relationship with `PurchaseOrder` (`RESTRICT` on delete to preserve audit history).

---

### 2.2. `Inventory`
Tracks the warehouse stock levels available for purchasing decisions and physical storage capacity.

| Field | Type | Modifiers / Constraints | Purpose & Rationale |
|---|---|---|---|
| `id` | Integer | PK, Autoincrement | Unique identifier for the inventory record. |
| `product_id` | Integer | FK (`products.id`), Unique, Not Null | Links to the unique product (ensures 1-to-1 inventory tracking per product). |
| `available_quantity` | Integer | Not Null, Check (`>= 0`) | Unreserved physical stock available for purchasing decisions after accounting for existing reservations. *(Note: `reserved_quantity` is omitted for MVP).* |
| `storage_capacity` | Integer | Not Null, Check (`>= 0`) | Maximum units this product can take up in storage without overflowing warehouse limits. |

**Rationale:**
Stockout risk depends directly on `available_quantity`. Storage capacity prevents purchasing quantities that the warehouse cannot physically accommodate.

---

### 2.3. `DemandForecast`
Captures projected consumption or sales over a defined time window.

| Field | Type | Modifiers / Constraints | Purpose & Rationale |
|---|---|---|---|
| `id` | Integer | PK, Autoincrement | Unique identifier for the forecast entry. |
| `product_id` | Integer | FK (`products.id`), Not Null, Index | The product for which demand is projected. |
| `forecast_quantity` | Integer | Not Null, Check (`>= 0`) | Estimated unit quantity required over the specified period. |
| `period_start` | Date | Not Null | Starting date of the forecast horizon. |
| `period_end` | Date | Not Null | Ending date of the forecast horizon. |

**Rationale:**
Allows calculating burn rates (e.g. daily average demand) and projecting when inventory runs out during a specific period.

---

### 2.4. `Supplier`
Represents vendors capable of supplying products.

| Field | Type | Modifiers / Constraints | Purpose & Rationale |
|---|---|---|---|
| `id` | Integer | PK, Autoincrement | Unique identifier for the supplier. |
| `supplier_name` | String(255) | Not Null, Unique, Index | Official company/vendor name. |

**Relationships & Deletion Rules:**
- `supplier_products`: One-to-Many relationship with `SupplierProduct`.
- `purchase_orders`: One-to-Many relationship with `PurchaseOrder` (`RESTRICT` on delete to preserve purchasing history).
- `purchase_recommendations`: One-to-Many relationship with `PurchaseRecommendation` (`RESTRICT` on delete).

---

### 2.5. `SupplierProduct`
Association entity defining commercial and logistics terms between a supplier and a product (Many-to-Many).

| Field | Type | Modifiers / Constraints | Purpose & Rationale |
|---|---|---|---|
| `id` | Integer | PK, Autoincrement | Unique record ID. |
| `supplier_id` | Integer | FK (`suppliers.id`), Not Null | Reference to the supplier. |
| `product_id` | Integer | FK (`products.id`), Not Null | Reference to the product. |
| `unit_price` | Numeric(10, 2) | Not Null, Check (`>= 0`) | Agreed unit cost for purchasing from this supplier. |
| `lead_time_days` | Integer | Not Null, Check (`>= 0`) | Calendar days from order placement until stock arrives at warehouse. |
| `minimum_order_quantity` | Integer | Not Null, Check (`>= 1`) | Smallest order batch size accepted by this supplier (MOQ). |

**Constraints:**
- Unique Constraint on `(supplier_id, product_id)` ensures a single commercial profile per supplier-product pairing.

---

### 2.6. `PurchaseRecommendation`
Stores purchasing suggestions generated by the decision engine / AI agent for human review.

| Field | Type | Modifiers / Constraints | Purpose & Rationale |
|---|---|---|---|
| `id` | Integer | PK, Autoincrement | Unique recommendation identifier. |
| `product_id` | Integer | FK (`products.id`, ondelete="RESTRICT"), Not Null | The product needing replenishment. |
| `recommended_quantity` | Integer | Not Null, Check (`>= 0`) | Proposed quantity to order. |
| `supplier_id` | Integer | FK (`suppliers.id`, ondelete="RESTRICT"), Nullable | Suggested supplier (nullable if undecided). |
| `requested_delivery_date` | Date | Not Null | Date by which replenishment must arrive to avoid stockout. |
| `status` | String(50) | Not Null, Default `'PENDING'` | Lifecycle / approval workflow status (`PENDING`, `APPROVED`, `REJECTED`, etc.). |
| `agent_suggested_quantity` | Integer | Nullable, Check (`>= 0`) | Quantity proposed by the AI purchasing agent upon evaluation. |
| `agent_suggested_supplier_id` | Integer | FK (`suppliers.id`, ondelete="RESTRICT"), Nullable | Alternate or confirmed supplier recommended by the agent. |
| `agent_reasoning` | Text | Nullable | Detailed explanatory justification for the agent's evaluation. |
| `agent_decision` | String(20) | Nullable, Check (`IN ('ACCEPT', 'MODIFY', 'REJECT', 'INVESTIGATE')`) | The agent's evaluation decision. Kept distinct from human approval `status`. |
| `evaluated_at` | DateTime | Nullable | Timestamp recording when the agent's evaluation was performed. |

---

### 2.7. `PurchaseOrder`
Records committed or historical purchase orders placed with suppliers.

| Field | Type | Modifiers / Constraints | Purpose & Rationale |
|---|---|---|---|
| `id` | Integer | PK, Autoincrement | Unique purchase order ID. |
| `product_id` | Integer | FK (`products.id`, ondelete="RESTRICT"), Not Null | Product ordered. |
| `supplier_id` | Integer | FK (`suppliers.id`, ondelete="RESTRICT"), Not Null | Vendor fulfilling the order. |
| `recommendation_id` | Integer | FK (`purchase_recommendations.id`, ondelete="SET NULL"), Nullable | Traces the PO back to the recommendation that originated it (nullable for manual/existing orders). |
| `quantity` | Integer | Not Null, Check (`>= 0`) | Total units ordered. |
| `unit_price` | Numeric(10, 2) | Not Null, Check (`>= 0`) | Agreed price per unit at order creation. |
| `expected_delivery_date` | Date | Not Null | Date supplier has promised/scheduled delivery. |
| `status` | String(50) | Not Null, Default `'OPEN'` | PO status (`OPEN`, `RECEIVED`, `CANCELLED`). |

---

### 2.8. `PurchasingBudget`
Tracks available capital and expenditures committed to purchasing for the period.

| Field | Type | Modifiers / Constraints | Purpose & Rationale |
|---|---|---|---|
| `id` | Integer | PK, Autoincrement | Unique budget record ID. |
| `total_budget` | Numeric(12, 2) | Not Null, Check (`>= 0`) | Total expenditure allocation for the purchasing cycle. |
| `committed_amount` | Numeric(12, 2) | Not Null, Default `0.0`, Check (`>= 0`) | Funds already committed through open/completed purchase orders. |

---

## 3. Transactional & Integrity Invariants

1. **Atomic PO & Budget Commitment**:
   - Creating a `PurchaseOrder` and updating `PurchasingBudget.committed_amount` must occur in a **single database transaction**.
   - If either operation fails or violates a constraint, the transaction rolls back completely to prevent inconsistent budget tracking.
2. **Preservation of Purchasing History**:
   - Deleting a `Product` or `Supplier` with existing `PurchaseOrder` or `PurchaseRecommendation` records is blocked via `ondelete="RESTRICT"`, preventing accidental deletion of financial and operational history.
3. **SQLite Foreign Key Enforcement**:
   - Engine connection listener executes `PRAGMA foreign_keys=ON` on every SQLite connection.
4. **Deterministic Table Creation**:
   - `init_db()` explicitly imports all model modules prior to invoking `Base.metadata.create_all()`.
